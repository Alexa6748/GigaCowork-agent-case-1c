# Правила распределения ФУЛ (версия 1.0)

Все решения принимает скрипт `scripts/distribute.py` по этим правилам. Значения, которые можно менять без правки кода, лежат в `config.json`.

## 1. Чтение файлов

- Тип файла (ФУЛ из 1С / реестр Cloud / сотрудники 1С) и нужные колонки определяются по заголовкам. Порядок колонок, лишние колонки, имя листа, строки над заголовком (до 30) не мешают.
- Сравнение заголовков и значений — без учёта регистра, «ё/е», знаков препинания и лишних пробелов.
- Файл, в котором есть лист «Журнал решений» (результат прошлого запуска), пропускается.

## 2. Статус ФУЛ

| Ситуация | Решение | Что делает агент |
|---|---|---|
| Статус ФУЛ в 1С содержит «удал», «отмен», «аннулир» | Не обработан | Строку не создаёт, «Требует внимания» |
| В комментарии нет номера заказа S + 7 цифр | Не обработан | Заказ «не определено», строку не создаёт, «Требует внимания» |
| В комментарии несколько разных номеров | Не обработан | То же |
| Номер записан с кириллической «С» | — | Приводится к латинской S, отмечается в журнале |
| Заказ есть в Cloud, дата ФУЛ = «Дата получения УЛ» в Cloud | Уже учтён в Cloud | Ничего не делает (это исходный ФУЛ) |
| Заказ есть в Cloud, в комментарии уже есть «Повторная отправка ФУЛа, [дата этого ФУЛ]» | Уже учтён в Cloud | Ничего не делает |
| Заказ есть в Cloud, иначе | Повторная отправка | Строку не создаёт; дописывает в комментарий «Повторная отправка ФУЛа, ДД.ММ.ГГГГ» (дата ФУЛ). Если поставщик в 1С и Cloud разный — «Требует внимания» |
| Заказа нет в Cloud, в пачке несколько ФУЛ по заказу | Первый по дате — новый (или пропуск), остальные — «Дубль в пачке» | Одна строка; в её комментарий — «Повторная отправка ФУЛа, [дата дубля]» |
| Заказа нет в Cloud, дата ФУЛ раньше последней «Даты получения УЛ» в Cloud | Возможный пропуск | В новые строки не включает; лист «Возможные пропуски» с предложенной строкой |
| Заказа нет в Cloud, дата не раньше последней записи | Новый | Строка Cloud |

## 3. Группа логистов

| Способ доставки | Страна отправления | Группа |
|---|---|---|
| air | любая, в т. ч. пустая | Авиаперевозки |
| sea, truck, railway, direct truck | Китай, КНР, Гонконг, Hong Kong, HK… | ВЭД |
| sea, truck, railway, direct truck | другая | Мультимодальные перевозки |
| не air | пустая | не определено |
| пусто или неизвестное значение | — | не определено |

Если группа не определена, логист не назначается, строка создаётся с «не определено» в недостающем поле и попадает в «Требует внимания».

## 4. Кто может получать заказы

- Должность определяет группу: «авиа» → авиаперевозки, «ВЭД» → ВЭД, «мультимодал» → мультимодальные.
- Не получают заказы: ассистенты, помощники, руководители, начальники, директора, заместители, стажёры.
- Доступен только сотрудник в состоянии «Работает». Любой отпуск, декрет, «Уволен» и неизвестное состояние — недоступен.

## 5. Выбор логиста

Для каждой пары «поставщик + группа» в пачке (в порядке времени первого ФУЛ):

1. **История.** По реестру Cloud считается, сколько заказов этого поставщика вёл каждый логист группы (статусы «в работе» и confirm). Логисты, которых нет в списке сотрудников, не учитываются.
2. Если у самого частого логиста (или нескольких с равным счётом) кто-то доступен — назначается он; при равенстве — наименее загруженный из них.
3. Если самый частый логист недоступен — назначается **наименее загруженный доступный логист группы** (не «второй по истории»).
4. Если истории нет (новый поставщик) — наименее загруженный доступный логист группы.
5. Загрузка = число заказов «в работе» в Cloud + заказы, уже назначенные в этой пачке.
6. Ничья по загрузке — по алфавиту ФИО, затем по табельному номеру.
7. Все заказы поставщика в этой группе в пачке получает один логист.
8. Нет доступных логистов — логист не назначается, заказ в другую группу не передаётся, «Требует внимания».
9. Возможные пропуски распределяются после новых заказов по тем же правилам (как предложение).

## 6. Сопоставление имён Cloud ↔ 1С

«Кузнецова М.», «Кузнецова М.П.», «соколова и.ю.», «Федоров П.И.», «И.О. Фамилия» сопоставляются с ФИО: фамилия совпадает полностью, инициалы или имя/отчество — с соответствующими частями ФИО. «Белова И.» не совпадает с «Белов Игорь…». Если подходят несколько сотрудников — имя считается неоднозначным: такие строки Cloud не учитываются в истории и загрузке, вопрос выносится в «Требует внимания».

## 7. Поставщик

Сравнение без регистра, кавычек, знаков, пробелов и организационно-правовых форм (ООО, Co., Ltd, S.r.l., A.Ş. и т. п.). В строку Cloud пишется написание поставщика из реестра Cloud; для нового поставщика — из первого ФУЛ пачки.
