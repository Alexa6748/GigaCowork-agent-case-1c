# Агент распределения ФУЛ — установка и запуск

## Состав архива

| Файл | Что это |
|---|---|
| `ful-distribution.zip` | Навык: `SKILL.md`, `scripts/distribute.py`, `references/` (справочник правил, форма Cloud, шаблон ответа) |
| `system_prompt.txt` | Системный промпт агента |
| `ИНСТРУКЦИЯ.md` | Этот файл |

Требования к среде: Python 3.8+, `openpyxl` (чтение и запись .xlsx), `xlrd` (только если выгрузки приходят в .xls). Сеть не нужна.

## Установка в GigaCowork

1. Создайте агента, например «Распределение ФУЛ».
2. Вставьте в поле системного промпта текст из `system_prompt.txt` целиком.
3. Загрузите навык из `ful-distribution.zip` (внутри — папка `ful-distribution` с `SKILL.md` в корне) и подключите его к агенту.
4. Убедитесь, что агенту разрешён запуск Python-скриптов навыка и запись файла результата в рабочую папку.

## Запуск

1. Выберите агента.
2. Приложите три файла: выгрузку ФУЛ из 1С, реестр Cloud, список сотрудников из 1С. Порядок, имена файлов и листов не важны; допускаются .xlsx, .xls, .csv; можно приложить одну книгу с тремя листами.
3. Отправьте сообщение **без текста**.

Агент вернёт короткий ответ (сколько новых строк, повторных отправок, пропусков и вопросов) и файл `Распределение_ФУЛ_<дата>.xlsx` с листами:

| Лист | Содержание |
|---|---|
| Сводка | Итоги и какие файлы/листы распознаны |
| Новые строки Cloud | 12 колонок в порядке реестра — переносятся в Cloud после проверки |
| Повторные отправки | Что дописать в комментарий существующих заказов и дубли внутри пачки |
| Возможные пропуски | ФУЛ раньше последней записи Cloud, которых нет в Cloud, — с предложенной строкой |
| Требует внимания | Что не так, что сделал агент, что решить человеку |
| Журнал решений | Решение и основание по каждому ФУЛ, кандидаты группы с загрузкой и историей |
| Загрузка логистов | В работе до пачки, назначено сейчас, после пачки |

## Запуск без GigaCowork (проверка)

```bash
pip install openpyxl xlrd
python3 ful-distribution/scripts/distribute.py --inputs <файл ФУЛ> <файл Cloud> <файл сотрудников> --out ./result
# или папкой: --inputs ./входные_файлы
```

В stdout — готовый ответ для чата; код возврата 0 — успех, 2 — не хватает входных данных.

## Изменение правил

Без правки кода в `references/config.json` меняются: синонимы заголовков, список стран «Китай», способы доставки, ключевые слова должностей (группы и исключаемые роли), состояния «Работает»/отпуск/уволен, значения статуса Cloud «в работе», шаблон комментария о повторной отправке, слово «не определено». Логика выбора логиста описана в `references/rules.md`; её изменение согласуется с заказчиком.
